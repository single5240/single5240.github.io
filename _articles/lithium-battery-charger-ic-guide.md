在带电池的嵌入式产品开发中，很多软件工程师调通了 MCU 驱动和 [电量计管理]({{ '/articles/battery-management-portable-design.html' | relative_url }})，却经常在硬件联调阶段被一个现象卡住：**设备明明插着电源，充电指示灯却一直亮着不转灯，或者整机一边开机运行一边充电时，电量始终停在半路充不满**。

问题往往不在 MCU 代码里，而是**充电 IC（Charger IC）的工作边界与电源路径设计**被忽略了。充电 IC 在电路中同时协调**外部输入电源、系统负载与电芯**三方关系：既要安全地把外部电源能量送进电芯，又不能让系统负载干扰满充判断，还要防反灌和过热。

> **适用范围说明**：本文以最常见的**单节 4.2 V 锂离子电池**为例展开分析。市面上也存在 `4.35 V` 等高压规格电芯，实际满充电压必须以电芯规格书为准；磷酸铁锂（LiFePO4）、镍氢（NiMH）或多串电池包有完全不同的电压平台与充电策略，不能直接套用单节 `4.2 V` 参数。文中涉及的功耗与电流拆分为典型**理论算例**，用于建立数量级直觉，不代表特定 PCB 的实测温升结果。

## 为什么 5 V 不能直接给锂电池充电？

USB 接口或常见适配器提供的是 `5 V` 直流电源，而单节锂离子电池的标称电压通常只有 `3.6 V` 或 `3.7 V`，满充限制电压通常是 `4.2 V`（参考单节锂电池规格与充电芯片资料）。这两条电压线本身就不在一个安全平面上。

### 直接接 5 V 与“串联一个二极管”为什么都不行？

- **直接用 5 V 给电芯充电**：电源电压明显高于 `4.2 V` 满充上限，电芯会被持续过压、过流灌入能量，不仅会加速衰减，还会带来鼓包和热失控风险。
- **串联一只二极管降压**：这是初学者常想到的“土办法”。且不论硅二极管或肖特基二极管的正向压降会随电流与温度漂移——当充电接近尾声、电流减小到毫安级时，二极管压降会同步缩小，后端电压仍可能逼近甚至超过 `4.2 V`——更重要的是，二极管只能单向降压，**既不能按电池状态限制恒流，也无法实现精确恒压和满充截止，更不具备温度监测和防过流能力**。

因此，充电系统必须由专门的充电 IC 担任“阀门 + 管家”，把外部 `5 V` 变换并约束成符合电芯化学特性的充电过程。

## 充电 IC 的核心职责：预充、恒流、恒压与截止

一颗标准的单节锂电池充电 IC（无论是早期的线性芯片 `TP4056`，还是开关型芯片）都要严格执行以下四个阶段的状态切换，而非简单输出固定电压：

```text
电压/电流
  ^
4.2 V |----------------------------------+==================  (Vbat)
      |                                 /|
      |              CC 恒流            / |   CV 恒压
      |        +-------------------+   /  |
 I_cc |--------|                   |--/   |
      |        |                   |      |\
      | 预充   |                   |      | \
I_pre |-+------+                   |      |  \___ I_TERM (截止停充)
  0   +--------+-------------------+------+------+---------> 时间
       深度亏电     进入主充电区      到达4.2V  电流回落至阈值
```

1. **预充（Precharge）**：当电芯深度亏电、端电压低于预充阈值时，电池内阻高且活性材料状态脆弱，不能直接用大电流猛充。充电 IC 会先用较小的预充电流缓慢把电芯“唤醒”，等电压回到安全区间后再放开大电流。
2. **恒流充电（CC，Constant Current）**：电压进入正常区间后，充电 IC 将输出电流限制在设定值（例如 `0.5 A`）保持恒定，电芯端电压随能量积累逐步上升。
3. **恒压充电（CV，Constant Voltage）**：当电芯电压攀升到目标调节电压（如 `4.2 V`）时，芯片切换为恒压控制，死守输出端 `4.2 V` 不再抬高。随着电芯内部逐渐接近饱和，电压差缩小，充电电流自然衰减。
4. **满充截止（Termination，`I_TERM`）**：很多工程师会误以为“到了 `4.2 V` 一直浮充着也没事”。实际上锂离子电池长期被钳位在 `4.2 V` 会显著加速寿命衰减。当恒压阶段电流回落到截止阈值 `I_TERM` 以下时，充电 IC 会主动停止输出（结束充电），之后仅在电池电压跌落到再充阈值（Recharge Threshold）以下时才重新开启补电。

> **核心归纳**：任何合格的单节锂电池充电 IC，最本质的职责可以浓缩为三件事——**限流**（预充 + CC）、**稳压**（CV `4.2 V`）、**截止**（`I_TERM` 停充）。

## 拓扑选型：线性充电（Linear） vs 开关充电（Buck）

确定了充电曲线后，能量从 `5 V` 降到电池电压主要有两条实现路径：**线性调节**与**开关降压（Buck）**。

### 线性充电的热损耗算例与热调节（Thermal Regulation）

以经典的线性充电芯片（如 `TP4056`）为例，芯片内部相当于一颗受控的可变电阻/调整管串在输入和电池之间，输入与电池之间的压差会直接变成芯片自身的热耗散：

```text
P_loss = (Vin - Vbat) × Ichg
```

代入一组**理论算例**：假设输入 `5 V`，电池当前处于 `3.5 V`，设定充电电流为 `0.5 A`，那么在充电 IC 内部消耗掉的功耗约为：

```text
(5 - 3.5) V × 0.5 A = 0.75 W
```

需要注意：**`0.75 W` 是热损耗功率算例，不能直接等价于某一个固定的摄氏度温升**。真实芯片温度还取决于封装热阻、PCB 敷铜散热面积和环境温度。线性芯片通常配有**热调节（Thermal Regulation）**功能：当芯片结温逼近安全上限时，它会自动主动压低充电电流来“自保”，结果就是用户觉得板子没烧坏，但充电速度明显变慢了。

### Buck 开关充电与四维工程对比

Buck 开关充电 IC（如 `BQ25601` 所属拓扑）利用高频开关管配合功率电感和输入/输出电容做能量搬运，把压差转成电磁能量周期传递，而不是靠电阻发热消耗，因此在压差大或充电电流大时优势明显。

| 评估维度 | 线性充电 IC（如 `TP4056`） | Buck 开关充电 IC（如 `BQ25601`） | 选型指向 |
| --- | --- | --- | --- |
| **效率与发热** | 压差全部变成热量，大电流/低压电池段发热显著 | 转换效率高，发热明显更低，适合大电流快充 | 小电流（数百 mA）可用线性；`1 A` 以上或高温环境优先考虑 Buck |
| **PCB 面积与外围** | 无需功率电感，只需少量阻容，布板极简单 | 必须放置功率电感及较大输入/输出电容，且需注意开关回路布局 | 空间极紧凑的低功耗小设备优先考虑线性 |
| **EMI 与电源噪声** | 无高频开关动作，不向外辐射开关噪声 | 存在开关纹波与开关节点 `dV/dt`、`dI/dt`，易干扰模拟/射频前端 | 高灵敏度音频、ADC、无线前端旁优先线性或做好隔离滤波 |
| **BOM 成本** | 芯片与外围成本都极低 | 芯片单价叠加功率电感，整体成本更高 | 成本敏感型穿戴或小电池设备常选线性 |

## 关键外围引脚与常见硬件/软件踩坑

选定拓扑之后，原理图与固件联调时最容易出错的是几个外围控制脚与“职责边界误解”。

### 1. `PROG` 电阻：决定充电电流与匹配阈值

许多独立控制型充电 IC 通过一颗接地的 `PROG` 电阻来设定恒流阶段电流（部分芯片还会按固定比例联动 `I_TERM` 截止电流）。
- **常见坑**：焊错阻值单位（如 `kΩ` 看错成 `Ω`）、焊盘虚焊导致开路，或者直接把芯片 A 的 `PROG` 电阻表抄到芯片 B 上。不同家族芯片的 `PROG` 参考电压和换算系数完全不同，**必须逐字核对当前所用芯片的数据手册公式**。

### 2. `NTC` 引脚：电池温度监控不等于芯片结温保护

很多软件工程师以为芯片内部已经有过温保护了，外部 `NTC` 就可以悬空不管。这是两个完全不同的监测对象：
- **芯片结温调节/关断**：测的是 **IC 硅片本身**的温度，防止封装烧毁；
- **`NTC` 引脚**：通过电芯旁的热敏电阻检测 **锂电池本体**的温度，防止电芯在过冷或过热条件下充电引发析锂或鼓包。

> **设计禁忌**：如果项目所用电池确实不带 NTC 热敏电阻，**绝对不能直接将 `NTC` 引脚悬空**（极易因干扰误判高低温停充），也**不能凭直觉直接接地或接 `VCC`**。必须翻阅该型号芯片的数据手册，按照官方给出的“禁用温度检测（Disable TS/NTC）”标准分压电阻网络或上/下拉接法处理。

### 3. 状态引脚（`CHRG` / `STDBY` / `STAT`）与开漏耐压陷阱

多数充电 IC 的充电状态指示引脚都是**开漏输出（Open-Drain）**：
- 在有效状态时内部 MOSFET 导通把引脚拉低到地；非有效状态时释放为高阻态（故障态下部分芯片还会输出特定频率脉冲）。
- **坑一（漏掉上拉）**：如果 MCU 将读取状态的 GPIO 配成浮空输入、又没接外部上拉电阻，引脚高阻态时电平悬空不确定，固件读到的充电状态就会随机跳变。
- **坑二（倒灌高压）**：原理图常见习惯是把 LED + 限流电阻接到 `5 V` `VBUS` 上再连回 `STAT` 引脚。如果 MCU 的 GPIO 同时挂在同一条线上去读状态，而该 MCU 的 IO 是不耐 `5 V` 的 `3.3 V` 口，一旦芯片释放开漏输出，上拉网络就会把高于 `3.3 V` 的电压灌进 MCU 引脚。**正确做法是将 MCU 侦测用的上拉参考电压接到 `3.3 V`（同时核对两端芯片手册允许的引脚耐压范围），或通过分压/隔离电路接入**。

### 4. 电池保护 IC 不能替代充电 IC

许多锂电池包自带一层小电路板（俗称保护板，上面常能看到 `BQ297xx` 一类的锂电保护 IC 和背靠背 MOSFET），于是有人会问：“既然电池有保护板，是不是就不用充电 IC 了？”

答案是否定的。**保护 IC 与充电 IC 处于完全不同的两层逻辑：**

| 对比项 | 电池保护 IC（如 `BQ297xx` 系列） | 充电管理 IC（如 `TP4056` / `BQ24074` / `BQ25601`） |
| --- | --- | --- |
| **角色定位** | 事故前的**最后一道物理保险丝** | 正常充放电周期的**精密能量管家** |
| **主要职责** | 监测电芯过压、欠压、充/放电过流、短路，越界时切断 MOS 管 | 精确执行预充、CC 恒流、CV `4.2 V` 稳压、`I_TERM` 截止及热调节 |
| **能否单独完成充电** | **不能**。它不稳压 `4.2 V`、不限恒流、也不做 `I_TERM` 截止；触发保护时往往已经越过正常充电边界 | **能**。但仍需电池侧保护 IC 兜底防范外部故障或短路 |

保护 IC 守的是安全底线，充电 IC 管的是日常工作点，二者各司其职、互不替代。

## 核心陷阱：为什么“插着电却充不满”或反复微充？

回到文章开头的经典故障：**设备边开机边充电，指示灯一直停留在充电状态，或者电芯长期被电压拖着下不来。** 根源通常在于电源与电池、负载的连接拓扑——也就是硬件上直接把系统负载和电池**并联**在充电 IC 输出端（俗称“简单并接”或未做路径隔离）。

### 并联供电下的电流分流与截止误判（Microchip AN1149）

当系统负载与电池直接并联到充电 IC 输出端时，拓扑如下：

```text
                +-------> I_load (例如 0.2 A) -----> [ 系统负载 / MCU ]
                |
[ 充电 IC ] ----+ (IC 只能测到这里流出的总电流 I_out = I_chg + I_load)
                |
                +-------> I_chg  (例如 0.3 A) -----> [ 锂电池 ]
```

在这个结构下会出现两个典型问题（参考 Microchip 应用笔记 `AN1149`）：

1. **充电电流被负载“分流截胡”（理论算例）**：如果充电 IC 设定输出上限是 `0.5 A`，而开机状态的系统负载自己吃掉了 `0.2 A`，那么真正流进电池的净电流就只剩 `0.5 A - 0.2 A = 0.3 A`，充电时长被迫拉长。如果系统瞬时功耗超过 `0.5 A`，电池甚至会在插着电源的情况下反向被消耗。
2. **更隐蔽的 `I_TERM` 满充截止失灵**：充电 IC 的电流采样电阻位于它**自己的输出端**，它测量的是 `I_out = I_chg + I_load` 的总和，**分辨不出哪部分流去了电池、哪部分流去了系统负载**。
   当电池实际上已经进入 CV 阶段并逐渐充满、`I_chg` 已经跌破截止阈值 `I_TERM` 时，只要系统负载 `I_load` 依然存在（例如持续消耗 `0.2 A`），总输出电流就始终大于 `I_TERM`！
   结果就是：**充电 IC 误以为电池还没充满，拒绝触发满充截止**——要嘛把电芯长期死顶在 `4.2 V` 造成寿命受损与安全隐患，要嘛一直撑到内置安全定时器（Safety Timer）超时报故障停机。

### 解决方案：Power Path 电源路径管理（如 `BQ24074`）

要彻底根治“边用边充无法截止”与“电池完全放空时插电不开机”的问题，规范做法是采用带 **Power Path（电源路径管理）** 的充电 IC（或按照 `AN1149` 搭建外置二极管/MOSFET 负载切换电路）。

以集成 Power Path 的芯片（例如 `BQ24074`）为例，芯片内部将系统供电端（`OUT`/`SYS`）和电池端（`BAT`）拆分成两条受控路径：

```text
                +----------------------------------> [ OUT / SYS: 系统负载 ]
                |                 ^
[ VBUS 输入 ] --+--> [ 输入开关 / 动态路径 ]           (外部优先直供系统，
                |                 |                   互不干扰 BAT 电流检测)
                +--> [ 独立充放电路径 ] -------------> [ BAT: 锂电池 ]
                                  |
                         (可精确单独检测 I_chg,
                          并在突发重载时 Battery Supplement 补电)
```

Power Path 带来的三个关键工程收益：
- **精确截止**：系统负载的电流从 `OUT` 走，输入优先直供系统；进入电池的支路电流由芯片独立计量。哪怕系统一直开机运行，只要进电芯的电流跌破 `I_TERM`，芯片依然能干净利落地结束充电，电芯不会长期被 `4.2 V` 拖着。
- **深度亏电即插即起**：哪怕电池已经彻底放空被保护板锁死，只要插上外部电源，`OUT` 端就能直接建立系统电压让 MCU 启动，不用干等电池慢充到开机门限。
- **电池补充供电模式（Battery Supplement Mode）**：当系统某个瞬间出现峰值大电流（例如射频发射、电机/蜂鸣器瞬间拉载）超过了外部适配器或 USB 口的输入限流能力时，内部连接电池与 `OUT` 的通道会顺滑开启，让电池临时配合输入电源一起顶住负载峰值，防止系统电压跌落重启。

## 软件可控（I²C）充电 IC 的固件常见坑

如果系统用到了更高集成度、带 **I²C 接口** 的开关充电/路径管理芯片（例如 `BQ25601` 等常见系统级芯片），固件工程师在编写驱动时还要重点防住三个容易忽略的状态陷阱：

1. **硬件上电默认值决定冷启动生死**：在 MCU 还没上电跑完 `main()` 之前的几十到几百毫秒里，充电 IC 完全按芯片手册写死的**默认硬件参数**工作（包括默认输入限流、默认充电使能状态）。如果电池已经亏到无法让 MCU 上电，却依赖固件通过 I²C 去“解除充电限制”，设备就会陷入死锁。设计阶段必须核对上电默认配置。
2. **寄存器易失性与掉电复位恢复**：一旦输入和电池同时掉电，或者芯片触发内部复位，之前 MCU 通过 I²C 写入的高电流配置、定制 `VREG`/`I_TERM` 就会全部退回出厂默认值。驱动不能只在开机初始化写一次就不管了，要在检测到电源接入中断或状态变化时重新校验核心配置。
3. **内置看门狗（Watchdog Timer）超时回退**：不少 I²C 充电 IC（如 `BQ25601`）内部自带看门狗定时器。只要开启或未关闭该功能，芯片就会要求主机 MCU 在规定周期内定期通过 I²C 喂狗（或复位看门狗位）。**一旦软件忘记喂狗或总线异常卡死，充电 IC 往往会自动清回安全默认限流甚至中止异常充电参数**，导致实际充电电流和预期完全不一致，排查时极容易当成“硬件虚焊”。

## 工程选型与故障排查清单

### 选型自查表

- [ ] **确认电芯体系与满充电压**：明确当前电芯是 `4.2 V` 还是 `4.35 V` 或其他化学体系，绝不默认照抄常见型号参数。
- [ ] **评估线性热耗散与效率边界**：用 `(Vin - Vbat) × Ichg` 估算最坏压差下的发热；小电流且讲究成本与低噪声选线性，大电流或受限散热优先选 Buck。
- [ ] **判断是否需要“边充边用”**：只要设备允许用户在插电状态下开机运行（尤其是整机功耗接近或大于 `I_TERM` 时），优先选用 **Power Path 芯片** 或规范负载隔离电路，不要直接并接电池与负载。
- [ ] **核查外围与接口细节**：`PROG` 阻值、无热敏电阻时 `NTC` 的手册指定禁用接法、`STAT` 开漏上拉电源与 MCU IO 耐压、以及 I²C 芯片上电默认限流和看门狗周期。

### “插着电充不满 / 不转灯”四步排查法

| 排查顺序 | 实操动作 | 现象与定位结论 |
| --- | --- | --- |
| **1. 对比待机与开机态** | 断开外设负载或让整机进入低功耗待机，只保留充电观察能否正常转灯 | **待机能正常截止、开机永远不停灯** → 高度怀疑是并联负载干扰了 `I_TERM` 判断（AN1149 典型问题），而非芯片损坏 |
| **2. 测量输入真实压降** | 用万用表或示波器**直接量充电 IC 的输入引脚 `VBUS`**，而不是只看适配器标称值 | 若导线压降过深或触发输入动态电源管理（VINDPM/IINDPM），IC 会主动缩减电流，并非程序没配对 |
| **3. 检查 `NTC`、`CE` 与 `PROG`** | 复核使能脚电平、`NTC` 引脚分压是否在芯片规定的有效温度窗口内、`PROG` 对地阻值是否正确 | `NTC` 悬空/漂移或超出温窗会直接暂停充电，常误表现为“灯在闪烁或无电流” |
| **4. 读回 I²C 状态与故障寄存器** | 若为 I²C 充电 IC，在出现降流或停充时读取 `FAULT`、`STAT` 与看门狗相关状态位 | 快速定位究竟是热调节触发、输入过流保护，还是未喂狗导致寄存器恢复了默认安全参数 |

## 总结与关联阅读

把单节锂电池充电 IC 放进整个嵌入式硬件架构里来看，逻辑其实非常清晰：**保护 IC 负责兜住事故底线，充电 IC 负责严格执行预充、恒流、恒压 `4.2 V` 与 `I_TERM` 截止这三件核心职责，并通过热调节、`NTC`、Power Path 路径隔离与 I²C 监管把能量安全送进电芯**。理解这层分工，再遇到“发热降流”“状态脚读数乱跳”或“插着电却充不满”，就能第一时间分清到底是电芯特性、并联路径还是固件寄存器在作祟。
