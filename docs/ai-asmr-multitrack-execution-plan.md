- 日期：2026-10-25
- 状态：首版代码及自动化回归完成；本次按用户明确要求审查后推送，最终听感、60 分钟实时运行及手机实机验收继续保留为待完成项目
- 页面：`projects/ai-asmr/index.html`
- 声学约束：[现有声音体系与声学方案](ai-asmr-expansion-plan.md)、根目录 `AGENTS.md`
- 技术边界：Jekyll、Liquid、HTML、CSS、原生 JavaScript、Web Audio API；保持零外部音频依赖

## 1. 目标与交付边界

将现有单分类声音发生器改为最多同时播放 4 轨的环境混音器。用户可以组合雨声、壁炉、敲击等声音，独立调整音量，在播放中增删和编辑轨道，持续聆听而无明显循环接缝、操作爆音或分类切换中断。

本文的“无缝持续播放”包含：

1. 连续底声跨缓冲区边界时没有可辨识的接缝或周期音量凹陷。
2. 随机事件持续演化，不把一组固定表演反复重播。
3. 加入、移除、静音、参数修改和场景切换平滑衔接。

不要求整个混音按固定长度精确重复。有限噪声缓冲区仍会重复，不能宣传为数学意义上的永不重复。

### 1.1 首版必须交付

- 现有 10 类声音均可作为独立轨道加入混音；最多 4 轨，允许同类不同材质并存。
- 每轨独立音量、静音、独听、编辑和移除。
- 统一播放、暂停、总音量、全局低通和睡眠定时。
- 无缝循环底声、共享前瞻调度、完整节点生命周期管理。
- 保留现有材质差异、非周期律动、双耳处理、主题和键盘访问。
- 基础组合“小雨＋松木壁炉＋精装书皮轻敲”完成连续播放验收。

### 1.2 后续交付

- 本地保存、恢复和删除混音场景；场景之间平滑切换。
- 根据后台实测结果决定是否引入 AudioWorklet。
- 根据实测资源余量决定是否提高轨道上限。

不在本轮引入录音导出、外部音频上传、云端合成、账号同步或固定时长编曲。

## 2. 现有结构与改造入口

以下是制定方案时的代码事实；实施前重新核对函数位置和当前工作区状态，不依赖固定行号。

- `state.activeCategory` 同时控制面板、触发器和调度，当前仅允许一个分类发声。
- `initAudioEngine()` 创建共用的背景噪声、滤波器、共振峰与增益节点，多种背景轮流复用它们。
- `startAudio()` 以互斥分支启动各类定时器。
- `switchCategory()` 切换分类时调用停止逻辑。
- `connectTo3DioStage()` 将各声音直接送入主滤波器，尚无独立轨道出口。
- 背景粉噪使用 8 秒缓冲区并设置 `loop = true`，没有显式的首尾接缝处理；实际可听程度尚未验证。
- 调度器和子事件大量依赖 `setTimeout()`，多个手法进度与随机游走状态保存在全局。

保留各材质的物理合成算法，重构其状态、节点归属、路由与时间参数。禁止临时改写全局分类来轮流调用旧触发器。

## 3. 用户交互契约

### 3.1 浏览、编辑、播放相互独立

- 分类导航仅切换浏览面板，不停止混音轨道；独立播放恢复原有分类切换时停止的行为。
- “加入混音”复制当前声音配置并生成唯一轨道 ID；后续修改浏览配置不反向改动已有轨道。
- 点击轨道的“编辑”后，面板明确显示正在编辑的轨道；更改只作用于该轨。
- 退出轨道编辑后恢复浏览配置，避免用户误改已有声音。
- 已有 4 轨时禁止新增，并提供可访问的原因提示；不得静默替换已有轨道。
- 主区域保留独立播放，不向混音列表添加轨道；右侧空混音点击“播放混音”时加入当前浏览声音后播放。
- 播放中加入轨道时淡入；暂停中加入只保存配置，等待统一播放。

### 3.2 静音与独听

- 静音保留用户音量值，通过独立门控增益控制声音。
- 多轨独听按集合处理：存在独听轨时，仅集合内且未静音的轨道可听。
- 取消独听恢复原静音和音量状态。
- 长时间不可听的轨道可以释放昂贵声源，但恢复时必须平滑重新进入，不补播积压事件。
- 移除最后一轨时回到停止状态，清理调度和睡眠定时显示。

### 3.3 总控、可视化与提示词

- 暂停语义为淡出并挂起播放，不承诺逐样本恢复完整表演；恢复时保留配置和合理的手法状态，重建调度基准。
- 睡眠计时到期统一淡出。时钟策略采用墙钟截止时间，页面恢复后若已到期则保持停止，不重新发声。
- 一个 Canvas 汇总各轨事件，事件附带轨道 ID；限制总粒子数，隐藏页面时停止绘制。
- 主区域播放按钮表达当前分类的独立播放状态，右侧拥有单独的混音播放按钮，两处状态互斥。
- 混音器吸附于右侧，可展开或收纳；收纳不停止播放。展开不改动主区域宽度与分类导航列数，面板可独立滚动。
- 提示词明确区分当前编辑声音和完整混音；混音描述包括各轨材质、相对强弱与空间关系，不承诺治疗效果。

## 4. 状态与资源所有权

### 4.1 全局状态

保存 `selectedCategory`、浏览草稿、`selectedTrackId`、混音播放状态、总音量、低通上限、睡眠截止时间和轨道集合。

用 `stopped / starting / playing / pausing` 等明确状态处理异步启停；连续点击时采用操作版本号或等价机制，使过期的 `resume()`、淡出清理回调不覆盖新状态。

### 4.2 每轨状态

每轨至少包含：

```js
{
  id, category,
  config,       // 材质、手法、音量、静音等可序列化参数
  runtime,      // 随机状态、手法进度、下一事件时间、运行代次
  output,       // 该轨全部声音的统一出口
  start(when),
  update(patch, when),
  stop(when),
  dispose()
}
```

- 每轨独占其滤波器、共振峰、声像、背景增益、声源注册表和手法状态。
- 共享一个 AudioContext、主总线、前瞻调度器和不可变缓冲区缓存。
- 轨道随机流相互独立；相同配置的两轨不能共用全部随机进度或完全相同的底噪读指针。
- 视觉事件与音频事件解耦，粒子关闭或降帧不得改变声音密度。
- 本地存储只保存带版本号的配置，不保存节点、定时器或运行期对象。

## 5. 音频路由与电平

```text
每轨：
连续底声 → 场景/掩体滤波与共振峰 → 底声自然调制 ┐
随机瞬态 → 材质包络与滤波 → 双耳处理           ├→ 轨道音量 → 静音/独听/生命周期门控
长音声源 → 自身包络与空间处理                 ┘

全部轨道 → 混音余量增益 → 全局柔化低通 → 动态压缩 → 总音量/统一淡变 → 输出
```

- 改造 `connectTo3DioStage()`，显式传入轨道目标出口，所有支路均不可绕过轨道控制。
- 自然起伏、用户轨道音量和生命周期淡变使用不同增益节点，避免彼此覆盖。
- 保留各轨内部双耳关系；轨道位置控制若未明确声学语义，首版不增加额外立体声压缩或重定位。
- 掩体切换同步更新底声 `lpScale`、`bedGainScale`、`peakingFreq / Q / Gain`，不能只改雨滴。
- 全局低通约束适用于所有声音路径；实施时统一审计现有倍率、动态漂移和频率钳位，避免轨道绕过约束。截止频率不是砖墙频谱边界。
- 校准各类基础电平并预留混音余量；不采用按开启轨数实时除法，避免新增微弱声音导致其他轨突然变小。
- `DynamicsCompressorNode` 用于控制动态，不视为严格砖墙限幅器。若验收发现峰值余量不足，先修正源电平、共振增益与总线余量，再评估专用限幅。

## 6. 无缝底声实现

### 6.1 首版：预处理循环缓冲区

1. 生成噪声时先预热粉噪滤波状态，丢弃预热样本，再采集实际素材。
2. 生成额外重叠区，离线进行首尾重叠融合，构成循环缓冲区；正确设置有效循环范围，避免重复计入重叠段。
3. 根据素材相关性选择融合窗：去相关片段可从等功率窗开始，高相关片段需防止叠加增响。
4. 不把缓冲区首尾简单淡到零，避免每圈出现音量凹陷；不只强行令首末样本相等。
5. 左右声道独立生成；不同轨道使用独立变体或偏移，并通过长尺度随机调制降低重复纹理。
6. 由音频节点执行循环，不依赖 JavaScript 在边界重启声源。

融合时长与缓冲区长度由离线波形、短窗 RMS 和耳机试听确定，不把初始参数写成已验证结论。接缝比较需包含底声独听，不能依赖其他轨掩盖瑕疵。

### 6.2 后续：AudioWorklet 连续生成

当有限循环纹理或后台调度成为实际问题时评估引入：

- 保存噪声滤波状态和随机生成状态，跨处理块持续生成。
- 不在音频处理函数中执行 DOM 操作、网络请求或频繁内存分配。
- 若还需改善随机瞬态的后台连续性，必须把相应事件生成/合成一并迁移；只迁移噪声不能解决主线程事件停顿。
- 仅在能力检测和模块加载成功后启用，失败则回退缓冲区方案；不把失败隐藏为成功运行。
- AudioWorklet 也不能阻止操作系统暂停音频会话。

## 7. 事件调度与取消

### 7.1 共享前瞻调度

- 初始检查周期约 25 ms、前瞻窗口约 150 ms，均为待测参数。
- 以 `audioContext.currentTime` 为基准，为窗口内事件安排 `start(when)`、包络及 `stop(when)`。
- 将触发器改为显式接受 `(track, when, event)`；双连点、轮指、释放声等子事件使用相对 `when` 的偏移。
- 可提前安排的子事件直接提交音频时间线，避免再通过子 `setTimeout()` 决定发声时间。
- 记录已安排声源，确保停止轨道时能取消未来声音，而不仅是清空主线程定时器。

### 7.2 防积压和资源上限

- 主线程迟到时跳过失效事件并重建下一事件基准，不补发全部漏声。
- 对每轮调度事件数量、每轨与全局同时发声数设置有限预算；初值在迁移最密集声音时通过测量确定并记录。
- 优先降低低价值装饰事件密度，不通过突然压低整体音量隐藏超载。
- 每轨运行代次用于使旧异步回调失效；取消调度不能影响其他轨。
- 前瞻窗口只覆盖短时抖动，不宣称它保证后台或锁屏播放。

## 8. 淡变、长尾与生命周期

初始参数：滑块 30–80 ms；静音 80–150 ms；轨道加入/移除 300–800 ms；场景切换 1–3 s。均需试听确认。

- 连续修改 AudioParam 时从当前自动化值衔接，避免重复设置造成跳变；兼容不支持 `cancelAndHoldAtTime()` 的环境时采用明确的包络状态记录。
- `setTargetAtTime()` 的时间常数不等于精确完成时间。需要确定清理时刻的淡出，使用有明确终点的包络。
- 参数修改优先平滑更新已有节点；材质拓扑变化创建新分支，与旧分支交叉淡变。
- 移除先停止新增事件，再淡出统一出口；到期停止活动声源、断开节点并释放引用。
- 长尾可以跨越后续事件；显式移除时经轨道淡出收束，不强行保留不可控尾声。
- 自然结束通过 `onended` 或等价生命周期机制移出声源注册表；音频时间不推进时不能仅依赖墙钟误判清理完成。
- 暂停后检查异步挂起结果；恢复前等待 `resume()` 成功，失败时更新 UI 并允许用户重试。

## 9. 文件边界

首版实际文件划分如下；混音器和页面交互暂合并，调度及节点所有权放在同一运行时，避免空壳模块：

```text
assets/js/ai-asmr/
  runtime.js      # 前瞻调度、节点所有权、循环噪声缓存及淡变
  groove.js       # 混音共享呼吸、随机乐句、前景呼应与有界节奏变化
  presets.js      # 十类声学参数及默认配置
  voices.js       # 独立合成实例，隔离节点、随机流和手法状态
  lab.js          # 唯一 AudioContext、混音总线、轨道控制、交互与 Canvas
```

- 页面保留 HTML、交互绑定与 Canvas，逐步移除旧内联引擎，不能让两套引擎并行发声。
- 复用共享样式变量和主题逻辑，内部入口资产使用 Liquid URL 过滤器，模块内部引用保持有效相对路径。
- 保留主题脚本先于共享 CSS 的加载顺序及共享资产版本查询。
- 不编辑 `_site/`。后续场景持久化按阶段 D 增加；以上五个文件已创建。

### 11.6 混音自然律动

按用户要求，为混音增加共享节奏与适度随机性，独立试听保持原有调度：

- 共享乐句由 4–6 个有微时差的慢拍组成，拍间时长通过均值回归缓慢漂移；每句有不同的起伏幅度、峰值位置与长度，避免固定网格和单一周期调制。
- 每轨拥有独立的平滑随机漂移；可听且音量非零的轨道轮流获得少量前景强调，静音和独听变化会更新参与者。
- 雨声、流水、壁炉等连续背景的音量变化较小；前景声音略多起伏。独立的律动增益节点只衰减，范围不超过用户推子的电平，不改写推子值。
- 事件间隔按共同呼吸和每轨漂移小幅变化。较慢的前景动作只作轻微拍位靠近，最多修正 45 ms；雨滴、水泡、密集键盘和长间隔自然事件不作拍点量化。
- 首次加入的前景声音错开进入；修改同一轨材质不重新附加首次进入延迟。双连点、轮指、抬指释放等手法内部子事件保持原有相对时序。
- 右侧“自然律动”默认开启，关闭时平滑恢复中性增益，新安排的事件间隔恢复原算法；已排程的事件不硬性重置，各声音原有自然随机性仍保留。该开关不作用于独立试听。
- 停止混音、切回独立播放时释放律动调度作用域；模型最多保留 64 个乐句，避免长时间运行积累历史数据。
- 单独验证入口：`node scripts/check-asmr-groove.mjs`，不需要浏览器或第三方依赖。固定种子的一小时模型时间模拟通过增益/间隔边界、平滑交接、独立随机流、音频前瞻查询一致性、开关旁路及存储有界检查。
- 模型测试中，四轨每 250 ms 采样的最大增益变化约 `0.00824`；背景增益跨度约 `0.0338`，前景约 `0.0821`。实际播放另有 0.65 秒参数平滑。这些是控制模型的数值，不等于整段声音的感知响度。
- 浏览器回归增加带律动的四轨离线渲染、运行期增益与事件调度联动、关闭后恢复中性增益、推子不变和独立试听不创建律动会话的检查。
- 一小时模型模拟不是一小时 Web Audio 实时运行，也不能代替最终耳机听感与手机实机验收；原发布门槛保持不变。
